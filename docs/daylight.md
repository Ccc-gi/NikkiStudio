# 精细等级的昼夜系统

精细等级不再是固定光照，而是由一台走满 24 小时的时钟驱动。太阳走一条真实弧线（纬度 45°N、赤纬 25°N 的盛夏）：日出 04:39，正午升到 69°，日落 20:21，之后继续沉到地平线以下 18.7°。方位同步横扫约 246°，所以投影的方向和长度都会跟着变。

太阳落下后，**月亮从对跖点接过直射光** —— 这正是满月在天文上的位置，所以月亮在日落时从东方升起，交接是自然的。太阳和月亮是**两盏独立的方向光**：如果用一盏灯在两者之间切换，日落那一刻它的方向会突然翻转 180°。

夜里是**皎洁的月光**而不是漆黑的夜：天空保持深蓝带星，但地面被偏冷的银白月光照亮，家具在夜里同样看得清、同样有接触阴影。这是真实月夜的画法——天空暗、地面亮，色温偏冷。

**投影也在日月之间交接。** 任何时刻只有一盏灯投射阴影，所以 `numDirLightShadows` 恒为 1，three 不需要重新编译场景材质；交接发生在两盏光强度相等的瞬间，而阴影强度恰好在那里淡到 0，所以看不到切换。用两盏灯同时投影会把阴影渲染的开销翻倍，用一盏灯中途改方向又会让投影甩过去，交接是唯一既正确又便宜的做法。

颜色与强度来自七个作者手调的关键帧，用 smoothstep 在它们之间插值：

| 时刻 | 画面 | 太阳高度 | 主光 |
| --- | --- | --- | --- |
| 01:30 | 深夜，星空 | −18.7° | 月亮 |
| 04:15 | 蓝调黎明，星渐隐 | −4.1° | 月亮 |
| 08:00 | 清晨 | +33.0° | 太阳 |
| 13:00 | 正午 | +69.1° | 太阳 |
| 18:00 | 黄金时刻 | +22.5° | 太阳 |
| 20:30 | 暮色（刚日落） | −1.2° | 天空余晖 |
| 22:30 | 夜晚，星出 | −14.8° | 月亮 |

正午那一帧刻意等于旧版精细档的参数，所以「正午」就是过去一直看到的那个画面。关键是**循环的**：列表在午夜处接回开头，而 22:30 到 01:30 之间是同一片夜空，所以时间可以一直往前跑而不出现接缝。

## 设置里的控件

`设置 → 画面与环境`，仅在精细等级出现：

- **时间** —— 0:00–23:45，拖动即可跳到任意时刻，光照每帧跟随。
- **自动调整** —— 勾选后时间自行循环。**循环时长** 控制走完一整天需要几分钟（1–10，默认 3）。
- **环境亮度** —— 与旧版等级共用，是曝光倍率。
- **高级（默认收起）** —— 光源方位、光源高度、光源强度、光源色温、雾浓度。

滑块前缀是「光源」而不是「太阳」：它们编辑的是**当前那盏直射光**，白天是太阳，夜里是月亮，另一盏自动保持为镜像。所以半夜拖动它们同样有反应，而不是对着一个已经落山的太阳空转。

## 手动模式

关掉 **自动调整** 后时间停住，高级区可编辑。这里的规则是**稀疏覆盖**：

- 打开高级区时，每个滑块显示的是当前时刻算出来的值，**你不动它，它就继续跟着时间走**。
- 一旦你拖动某个滑块，只有那一个参数被固定下来，其余仍在跟随。
- 切回自动调整即清除全部手动覆盖。

所以「关掉自动」这一刻画面完全不变——不会跳。色温滑块是唯一有细微差别的地方：光照里存的是作者手调的 RGB，而滑块是一维的色温轴，所以第一次碰它时颜色会有最多约 21/255 的偏移。为了让这个偏移足够小，七帧的日光与月光都被保持在黑体色轨迹附近（`tests/daylight_manual.mjs` 守住了上界，并且只统计光线真正照亮场景的那些时刻）。

手动模式下其余氛围（天空、半球光、雾）停在关掉自动的那一刻。想换氛围就切回自动、选好时刻、再关掉。

## 天空

天空是一张程序化绘本贴图（原创绘制，不依赖任何外部素材），按七个关键帧各烤一张 2048×1024，**共用同一个随机种子**——云和远山的形状位置完全一致，只有颜色不同，这样才能交叉淡化而不让云「变形」。夜晚的帧额外画上按方向均匀撒布的星点。

**月亮是一个 billboard**，不是烤进贴图里的圆盘：烤进去的话，随时间在两个关键帧之间过渡时会出现两个月亮。它挂在穹顶半径的 0.9 倍处，位置由月亮方向实时决定，透明度随月亮高度渐入。

运行时天空由**一个穹顶 mesh** 呈现：半径为 1、始终套在相机上，用 `depthTest:false` + 极负的 `renderOrder` 画在最底层。片元着色器按当前权重混合七张贴图，并在着色器里自行做 sRGB→线性解码（贴图以 `NoColorSpace` 上传，采样器不做转换），再走 three 的 tonemapping / colorspace 收尾——所以主渲染和有色调映射关闭的 PMREM 通道都能得到正确的线性值。

着色器里的采样循环是**手工展开**的：ANGLE 在 D3D11 上会拒绝用循环变量索引采样器数组（`array index for samplers must be constant integral expressions`）。权重判断是全绘制调用一致的，所以实际只会取到两张贴图。

### 关于拖动时的卡顿

**烤一张贴图**是最贵的一步（canvas 上要画近两千个云团），所以绝不逐帧重画。整张天空只在启动时烤七次，一次性约 27 ms。

**环境反射**（`scene.environment`）走 `PMREMGenerator.fromScene`，渲染的是只有穹顶的独立小场景。单次约 0.3 ms，但**节流到最多每 400 ms 一次**——快速拖时间滑块时金属和高光反射会略微滞后，直接光则是精确跟手的。

首次调用约 430 ms，因为要为「关闭色调映射」的 PMREM 通道再编译一次穹顶着色器；这一次性开销落在页面加载阶段，不在编辑过程中。

## 性能

RTX 4070 Ti / Chrome，精细等级：

| 项目 | 耗时 |
| --- | --- |
| `sampleDaylight()` 单次 | 0.0014 ms |
| 烤七张天空（冷启动 / 热） | 27 ms / 15 ms |
| 每帧穹顶渲染（含权重变化 + 跟随相机） | 0.022 ms（无天空基线 0.022 ms） |
| 每帧 `update()` 全部开销 | ~0.08 ms |
| 其中设置面板打开时的控件同步 | 0.004 ms |
| PMREM 稳态单次 / 首帧 | 0.3 ms / ~430 ms（一次性编译） |

天空贴图占 **56 MiB** 显存（七张 2048×1024，不生成 mipmap——穹顶从不缩小，mip 只会白占内存和生成时间）。

结论：昼夜系统每帧的成本不到 0.1 ms，约为 60fps 帧预算的 0.5%。自动循环时若不打开设置面板，控件同步被完全跳过。

## 验证

- `node tests/daylight_cycle.mjs` —— 七档权重恒和为 1、太阳与月亮弧线、午夜接缝、相邻时刻连续性、边界回绕。
- `node tests/daylight_manual.mjs` —— 空覆盖集是恒等变换、各覆盖只动自己的字段、日夜切换时控制的是对应的那盏光、色温往返不跳变。
- `node tests/lighting_profiles.mjs` —— 精细档由时钟驱动；正午太阳为主、午夜月亮接管；切回标准/轻量逐值恢复旧参数。
- 浏览器里用真实庭院存档检查：清晨/正午/黄昏/深夜的受光面与投影方向，拖动时间滑块的跟手程度，以及自动循环时的帧率。

这是浏览器实时预览光照，不包含游戏引擎的完整全局光照、材质特效或烘焙数据。高光仍取决于模型已有的金属度、粗糙度和法线。太阳高度很低时（接近 04:39 与 20:21），投影会拉得很长，可能超出阴影视锥而变淡——这是预览的固有限制，不是缺陷。
