# 架构

frontend 是从原研究工程迁移的正式网页编辑器；SaveDocument 保存完整原始 JSON，Three.js 场景仅作视图。

backend 是常驻回环 HTTP 服务，负责私有配置、输入校验、任务状态和请求验证。私有目录不在静态服务范围内。Host、Origin 与随机会话 token 共同约束配置、浏览目录及退出等变更接口。无密钥原文日志，无远端上传和密钥代理。

asset_pipeline 在进程中保留当前安装目录的已验证包索引。外部 CLI 是独立的转换后端，每批请求会启动解析器进程；当前尚不是长期驻留的 CUE4Parse provider，因此首次材质及蓝图请求有进程启动成本。接口与索引层独立，未来可以替换成驻留 .NET provider，无需改变前端。

0.1.1 将短时间内到达的模型请求合并为最多 32 项的批次，再按密钥 GUID 分组。相同模型并发请求共享任务，已有属性 JSON 和贴图不重复启动 CLI；同一材质的纹理引用批量转换。文件哈希按大小、时间及文件标识缓存，普通资源请求共享最多一秒的版本检查结果，发布新转换结果和状态检查仍强制重新核对。

游戏的空集合可能写成 Snapshots/PlaceInfo 的 `{}`。文档内部按空数组处理，但未改变时导出保留原始空对象；新增家具后才变为数组。切换文档时取消尚未开始的资源任务，旧任务结果不会覆盖新工作区。几何准备完成即可显示场景列表与编辑，贴图继续补齐。

预设把选中的物品存成一小段存档片段，一个预设一个 JSON，放在用户数据目录的 `presets/` 下（`backend/presets.py`）。内容是一组物品的类型、染色与相对整组最低点的变换，落点由放置时的鼠标位置决定；实例 ID、分组在放置时重新分配，同一组共用一次撤销。预设不参与资源版本指纹，也不进静态服务范围。

配置只构建目录和家具引用映射，使用一个临时网格/属性探针验证实际解析；探针不进入模型缓存。没有全家具预导出阶段。静态配置立即可索引，蓝图组件树在 `/api/item/{id}` 被使用时解析。GLB 从 `/asset/{fingerprint}/{package}` 请求时才生成。材质依据网格实际引用，在 `/api/material/{fingerprint}/{package}` 被请求时生成。

临时 staging 不修改游戏原件：utoc 始终复制，ucas/pak 能硬链接时硬链接。缓存与游戏跨卷时，优先在安装目录的同卷兄弟目录建立临时 staging，避免复制几十 GB；没有写权限或硬链接不可用时，检查空间再临时复制。原包没有写入操作，staging 随批任务结束清理。

转换失败不发布主要模型。校验成功才原子更新 active.json 指针。版本变化会建立新目录，不覆盖旧缓存；浏览器 URL 包含完整指纹。存档不依赖缓存是否完整，缺资源实例仍能往返保留。

目录覆盖规则依据 [CUE4Parse AbstractVfsReader.VerifyReadOrder](https://github.com/FabianFG/CUE4Parse/blob/master/CUE4Parse/UE4/VirtualFileSystem/AbstractVfsReader.cs) 的数字 `_P` 优先级；同最高优先级仍然歧义时拒绝选择。游戏解析规则放在 adapters；未知的新游戏结构必须补适配器和合成夹具再启用。
